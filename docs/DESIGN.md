# Hina 界面规范

界面基线以 `AGENTS.md` 第 11 节为准：中文、紧凑、扁平，以冷白表面、石墨文字和冰蓝强调色组织日常使用工具。使用系统字体、14px 正文和 12px 辅助文字，统一语义颜色、4/8/12/16/24/32px 间距及 6/8/12px 圆角 Token；不使用装饰性渐变、阴影或无功能图标。

## 当前消息日志页

- 仅保留单行标题、紧凑工具栏、消息列表和分页。移除介绍段落、重复统计、采集说明、同步时间等常驻文案；不设置手动刷新为正常流程。
- 表格逐条展示序号、时间、来源、会话分类、发送者、内容和处理状态；完整 ID、图片与模型响应放入按需打开的详情侧栏。仅有一个来源时不展示多余的来源筛选器。
- 搜索、按钮保留语义元素；禁止浏览器默认样式的下拉选择框、复选框和弹出菜单。筛选统一使用项目菜单组件，具备列表框语义、方向键、Enter、Escape、外部点击关闭与焦点恢复。
- 默认开启实时更新，新消息自动插入首页并更新条数，不以新消息提示要求用户再次操作。用户可主动暂停，恢复时自动追上最新记录；历史分页保留快照，并可返回最新页。
- 新消息不关闭详情，不重建已有图片；列表在顶部时跟随最新消息，向下阅读时保留可见消息的位置。侧栏约束滚动、管理焦点并支持 Escape 关闭。
- 图标统一使用 `@lucide/vue`，仅用于搜索、筛选、实时控制、主题、翻页及详情操作。QQ 图片附带的协议标记不在列表正文中展示，原始文本保留于详情。
- 明暗模式在应用根元素建立主题，不依赖外部宿主提供 Token。窄窗口下筛选换行，表格保留可读列宽并横向滚动。

## 验收要求

界面修改后以真实渲染检查 1280×800 和 900×700，覆盖明暗主题、空列表、错误、详情、筛选与分页；图片需检查实际加载或明确失败状态。单纯构建或源码检查不能代替视觉验收。每次实际验证结果记录在交付说明或相关功能文档，不预先宣称通过。

## 模型设置与处理状态

- 顶部提供消息日志/设置的页面链接；表单按“模型连接、回复、请求设置”组织，不建立无依据的 Tabs。API 地址、模型和 Secret Token 是常用字段，请求限制与提示词默认折叠。
- Token 输入使用密码类型，无显示开关，保存后清空；重新打开只显示“已设置，留空保留”，不回填密文或密钥片段。主操作为保存，连接测试为次操作；测试不隐式保存或启用回复。
- 回复与图片输入使用项目 Switch，范围和 Token 参数复用 `LogSelect`；输入和按钮保留语义元素，控件统一 36px。加载、测试中、保存中、成功、参数/权限/额度失败和重新读取均有明确状态。
- 消息详情用一行三个阶段展示输入、API、输出；正文不重复渲染第二份输出，输出区域只显示目标确认或失败类别。原始供应商错误体、请求头和 Token 不进入界面。
